## Code fixes

The storefront rendered plain `description`, so the rebuilt size table would have flattened
back into a run of numbers — and `page.tsx` fed that same string to `<meta name="description">`,
which is how `gid://shopify/Product/…` ended up in page metadata.

- `src/lib/shopify.ts` — `getShopifyProduct` now fetches `descriptionHtml` and `seo`.
- `ProductPageClient.tsx` — renders `descriptionHtml` when present, falls back to text.
- `page.tsx` — metadata and JSON-LD prefer `seoDescription`; JSON-LD `brand` now uses the
  product vendor instead of the hardcoded `'Odubo'`.

## Domain: moved to odubostudio.com

`odubostudio.com` (registered via Vercel) is **live and correct** — NS delegated to
Vercel, apex 308→www, www 200 with valid TLS, app serving. Nothing to wait on; it is
not a propagation issue.

`odubo.studio` is the dead one: registry says ACTIVE but it has **no NS delegation at
all**, so it and every subdomain resolve for nobody, and it has no MX.

Two live bugs fixed as a result: `hostname.includes('odubo.studio')` is **false** on
`odubostudio.com` (different string — no dot), so production detection failed on the
real production domain in both `middleware.ts` and `HomePageClient.tsx`. Both now
resolve the apex from the incoming host instead of hardcoding it. `sitemap.ts` and
`robots.ts` fallbacks repointed at `https://www.odubostudio.com`.

**Customer accounts are broken end to end:** `odubostudio.myshopify.com/account` 302s
to `https://account.odubo.studio/` — dead. Customers reach that from Shopify's own
order-confirmation emails, so it breaks the post-purchase path.
