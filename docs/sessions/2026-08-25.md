## Shipped

Three new suites (**109 tests**), all new files:

- **`src/__tests__/deviceInfo.test.ts`** (44) — the shared device/network brain
  behind the clips feed. Real UA strings for iPhone, iPad-in-desktop-mode,
  Android, Edge, Firefox, and the Instagram / Facebook / TikTok webviews that
  are the platform's actual traffic sources. Covers the network tiering,
  buffer profiles, prefetch window, render-window radius, scroll behaviour and
  PWA standalone detection. Each case re-imports the module because
  `getDeviceInfo()` memoises — reusing one import would silently assert against
  whichever UA ran first.
- **`src/__tests__/fileOrganization.test.ts`** (48) — R2 key generation. These
  strings are permanent object keys, so the assertions are literal. Supersedes
  the root `test-file-organization.mjs`, which printed to stdout, asserted
  nothing, and had drifted to a `fileType: 'track' | 'album-cover'` API that no
  longer exists.
- **`src/__tests__/rateLimit.test.ts`** (17) — the D1 throttle in front of login
  and Moments uploads. Weight is on database-failure behaviour, since a limiter
  that fails open under load is the same as no limiter. Confirmed: it does
  fall back to the in-memory limiter and keeps enforcing.

Two stale tests repaired (**source was correct in both cases**):

- `src/__tests__/emailTemplates.test.ts` — expected `/brand-logos/odubo-logo.png`;
  the committed asset is `Danceman_Logo_Red.png`. Expectation updated.
- `src/app/api/videos/__tests__/videos.get.test.ts` — tested a fallback-schema

## Bugs found and pinned as tests

Both are **live**, both are pinned with a failing-behaviour test that documents
the fix, neither is fixed here (both need a source edit, which this session
deliberately avoided):

1. **`.aac` uploads are unplayable.** `validateFileType` accepts `aac` as
   audio, but `getMimeType` has no entry for it — so the object is stored as
   `application/octet-stream` and browsers refuse to stream it. Fix: add
   `aac: 'audio/aac'` to the map in `src/lib/fileOrganization.ts`, or drop
   `aac` from `audioExts`.
2. **`getRateLimitInfo` reports a wrong `remaining`.** It takes no limit
   argument and hardcodes `10 - count`, so the number is wrong for every
   caller whose real limit isn't 10 — including the login throttle. Anything
   surfacing this as an `X-RateLimit-Remaining` header is lying to the client.
   Fix: take `limit` as a parameter.

Also documented (behaviour, not bug): `parseFilePath` labels its second
segment `galleryId`, but `generateFilePath` writes the **slugged gallery name**
there. The id is not recoverable from an R2 key — callers must not use that
field for lookups.
