## Completed Work

### 1. Clips Playback Fixes
**Problem:** Autoplay stopping after 2-3 clips, double-tap needed to resume, videos restarting on tap.

**Root Cause:** Dual playback control (ClipCard + ClipsFeed both calling `.play()`), `isPaused` state in effect dependencies causing re-triggers.

**Solution:**
- Single source of truth: ClipCard owns all playback
- Used refs (`userPausedRef`, `isPlayingRef`) for logic state, useState for UI state
- Separated HLS attachment from playback control into different useEffects
- Aggressive watchdog (1s interval) for mobile resilience

**Files Modified:**
- `/src/components/clips/ClipCard.tsx` — Complete rewrite of playback logic
- `/src/components/clips/ClipsFeed.tsx` — Removed competing playback control

## Debugging Notes

### Video Playback on Mobile Safari
- **Key Insight:** `play()` must be called synchronously in tap handler to preserve user gesture context
- **What Failed:** Async waits for `readyState` before `play()` broke gesture chain
- **What Worked:** Call `play()` immediately, let browser queue it if video not ready

### Effect Dependency Trap
- **Key Insight:** Using state for pause tracking caused effects to re-run
- **What Failed:** `isPaused` in dependency array triggered HLS re-attachment on every pause
- **What Worked:** Using refs for logic state (`userPausedRef`), state only for UI (`isUserPaused`)
