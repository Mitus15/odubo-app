# 2026-08-29 — Pose Studio to production: 5-minute takes + the contest photo path

Two jobs share the Pose Studio camera, and it served neither fully: promo
video for social (needs long takes), and album-cover contest entries on
Sept 26 (needs to be findable and durable). This session did both.

---

## What shipped

### Part 1 — the studio take

- **`src/lib/loop/pose/limits.ts`** (new) — every capture constant in one
  place. Clip length is a function of BOTH studio and filter:
  15s guest / 60s studio-filtered / **300s studio-raw**.
- **`src/lib/loop/pose/recorder.ts`** (new) — the `MediaRecorder` wrapper both
  capture paths share. Audio-aware codec list, mime read-back, `onerror`, a
  stop watchdog, 1s timeslices.
- **`src/lib/loop/capture/wake-lock.ts`** (new) — holds the screen for the
  duration of a take.
- **`src/lib/loop/capture/camera.ts`** — `startCamera` now takes options and
  returns what was actually granted. Resolution constraints (long-edge,
  orientation-aware, all `ideal`), optional mic with a picture-only retry.
- **`src/lib/loop/pose/video-engine.ts`** — delegates to the shared recorder;
  muxes the mic into the canvas stream; exposes `granted` / `hasAudio`.
- **`src/components/loop/pose/CameraSheet.tsx`** — the raw direct-stream path,
  a working cap, a live timer, the studio readout, size guards.
- **`PoseStudioShell.tsx` / `app/loop/pose/page.tsx`** — studio is now an
  admin-gated visible toggle; `?studio=1` is gone.

### Part 2 — the contest photo path

- **Findability.** "Try the Filter" is a full-width row on the Gathering
  poster. It was previously reachable only from inside the Cover Contest sheet.
- **Terms in the room.** `InRoom` gained a "How the cover contest works"
  surface. The explainer used to render only pre-event, so everyone actually
  shooting entries never saw the $50/$5 terms.
- **Honest copy.** Post says it enters the contest; Keep says it doesn't.
- **`GET /api/loop/gallery/mine`** (new) + `listCreditedPhotos` — "Yours" now
  merges the device gallery with the server credit ledger, so entries survive
  cleared storage and a new phone.
- **Camera error recovery** — recovery line + Try again button.
- **Accessibility** — `role="dialog"`, `aria-modal`, focus trap and focus
  restore on `MediaViewer` and `ModuleSheet`; opacity washes swapped for
  `.loop-muted` in touched files.

## Three pre-existing bugs found and fixed

1. **The auto-stop cap had never worked.** The `setTimeout` captured a stale
   `toggleRecord` where `recording` was still `false`, so on firing it took the
   *start* branch, hit the recorder guard, and showed "Recording isn't
   supported here" while the take kept rolling. Manual stop worked, which is
   why it went unnoticed.
2. **Studio mode had never produced HD.** `getUserMedia` asked for no
   resolution, browsers default to 640×480, and the render cap only ever scales
   down. The "HD" in `fcc9dd0` was a no-op on every device.
3. **The recorded blob carried the requested mime, not the real one.** Safari
   accepts a type then encodes what it likes; `recorder.mimeType` is now read
   back after `start()`.

Also fixed: `WallGallery.share()` hardcoded `.webm` for local items — the same
bug `fcc9dd0` fixed in `CameraSheet` but missed here.

## Verification

**Done:**
- `npm run build` succeeds; `/loop/pose` and `/api/loop/gallery/mine` are
  dynamic as expected.
- 19 new tests across `loopPoseLimits`, `loopInRoom`, `loopPoseStudioShell`.
  Full suite: 2 pre-existing failures (`emailTemplates`, `videos.get`),
  unchanged by this work.
- Browser: poster nav renders; studio toggle hidden for guests and present for
  a signed-in admin (confirmed both server-side via curl and in the browser);
  toggling flips the copy to "Studio · photo, 60s filtered or 5 min raw"; the
  camera error banner renders with its recovery line and Try again button.

**NOT done — the important gap:**

The Browser pane has **no video input device** and blocks camera access, so
**no recording path was exercised at all**. Everything about the actual take —
whether the 1920 constraint is honoured, whether audio muxes, whether 5 minutes
survives thermals and the wake lock, whether the cap now fires — is verified by
construction and unit test only.

This needs a real iPhone over HTTPS (production URL, not a preview deploy),
in this order:

1. Readout says 1080×1920 · 30fps. It goes amber if the constraint didn't take
   — that is the signal, and it is the whole reason the readout exists.
2. A guest recording left alone stops itself at 15s with no error (the cap
   regression).
3. A full 5-minute raw take: screen stays awake, no thermal frame-rate
   collapse, downloads to Files.
4. Mic audible; then re-test with mic permission **denied** — the take must
   still record picture.
5. Backgrounding mid-take ends it cleanly and keeps the partial file.
6. A 60s *filtered* studio take at 1920 — the open question inherited from
   `fcc9dd0`. If segmentation can't hold it, lower `RENDER_MAX_HEIGHT.studio`,
   not the clip limit.
7. End to end: `node scripts/loop/video-convert.mjs --in=<file> --scale=2` from
   the repo root (not the worktree — node_modules live there).

Contest path also unverified end-to-end: exercising camera → Wall → credit →
✦ feature → cover ballot needs the doors open, and this worktree's `.env.local`
points at **production D1**, so flipping them would have opened the real room
to the internet. Not done deliberately.
