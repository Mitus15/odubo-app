# 2026-08-10 — The Loop Journal (event enhancement + community magazine)

## Summary

Merged PR #3 (the sand/oxblood recolour) into `main`, then built **The Loop
Journal** — Loop Soul's per-volume community magazine — on branch
`feat/loop-journal`. Design rationale in `docs/decisions/loop-journal.md`:
the event enhancement and the magazine are one system; each volume's issue is
mostly written by the event itself and then sells the next volume.

## What shipped

- **Migration 144** (`database/migrations/144_loop_soul_journal.sql`) —
  `journal_issues` (editorial frame + publish flag) and `journal_moments`
  (curated photo list). **Applied to remote D1** via the app's own D1 REST
  layer (wrangler needed interactive auth; a tsx script through
  `src/lib/loop/db.ts` did not).
- **Data layer** — `src/lib/loop/journal-store.ts` (issue + moments CRUD,
  run-of-show store patterns) and `src/lib/loop/journal-server.ts` (assembles
  an issue: anthem champion re-derived via `buildBracket`, run of show,
  moments).
- **The magazine** — `src/app/loop/journal/page.tsx` +
  `src/components/loop/journal/JournalIssueView.tsx`. Poster mode (sand =
  paper, oxblood = ink), zero client JS, sections self-omit when empty.
  Unpublished: public sees a designed "still being written" state; a
  logged-in admin sees the live draft with a ribbon.
- **Wiring** — `LegacyHome` (now async): Journal card replaces the Iconic
  Moments stub; `GatheringPoster`/`GatheringHome`: "The Journal ↗" footer
  link when a published issue exists.
- **Admin** — `JournalEditor` panel on `/loop/admin` (headline, standfirst,
  publish toggle, Iconic Moments list) + `/api/loop/admin/journal` (gated by
  the existing middleware matcher). `ListEditor` in `ContentEditor.tsx` is now
  exported with an `endpoint` prop and shared by both panels.

## Verification

- `tsc --noEmit` clean (the only errors are pre-existing noise from
  `projects/StereoImager/**/compiler_depend.ts` — a JUCE CMake artifact that
  isn't TypeScript; consider excluding `projects/` in tsconfig).
- `npm run build` succeeds; `/loop/journal` page and
  `/api/loop/admin/journal` route both present in the output.
- Migration verified: `journal_issues`, `journal_moments` exist on remote D1.
- No Loop tests exist yet (Loop Soul shipped without them) — nothing to run.

## Known issues / notes

- The journal renders real data only after an admin drafts an issue; until
  then `/loop/journal` shows the "being written" state (by design).
- iTunes artwork + moment images use plain `<img>` (remote domains aren't in
  next.config image allowlist).
- Wrangler CLI can't run non-interactively here (`CLOUDFLARE_API_TOKEN` not
  set in the shell); remote migrations can be run with a tsx script through
  `src/lib/loop/db.ts` + `--env-file=.env.local`.
