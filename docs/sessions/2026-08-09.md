# 2026-08-09 — Loop Soul: green → house palette

## Summary

Recoloured the `/loop` surface from its electric-green identity to the Loops
Soul poster's own palette. Branch `feat/loop-brand`, PR #3.

## How this started in the wrong place

The brief was "make the Loop Soul branding closer to my brand colours — the
off-wine reddish brown and the glassmorphism rather than the green, but still
with the black silhouettes." I searched this repo, found no green, and built a
brand surface for `/loops-soul` (the older Moments episode layer) instead.

That was wrong. The green was in a Loop Soul Hub project that landed on `main`
**during** this session via PR #2, at `/loop`, with a `.loop-theme` block whose
own comment describes it as "electric-green field, deep-black silhouettes" —
exactly what was being described. Local `main` was 10 commits behind and I
hadn't re-fetched.

Lesson recorded in memory: `git fetch` before trusting local `main` in this
repo, and confirm which surface the owner can actually see before styling one.

The `/loops-soul` work is preserved, unmerged, on `feat/loops-soul-brand`.

## What shipped (PR #3)

- `@theme` tokens revalued **and** renamed (`electric` → `sand`, 60 utility
  usages across 26 files); `--color-ink` moved from neutral `#050505` to warm
  oxblood `#2a0f0a`
- Vault/Legacy mode flips to an oxblood field with sand ink
- `.loop-glass` for surfaces that float above the poster (`GetPassModal`,
  `ModuleSheet`), tinted from whichever field it sits on, opaque `@supports`
  fallback for in-app browsers
- Artwork recoloured — see below
- `docs/decisions/loop-soul-palette.md` for the token map and rationale

The field is sand, not wine, and that is deliberate: the poster's mechanic is
flat black silhouettes on a bright field. Green held ~12:1 against black, sand
holds ~10:1, wine would have been ~2:1 and sunk the crowd artwork. The reddish
brown became the ink instead, which is how the printed poster is arranged.

## Three defects caught by rendering, not by reading

1. **Green was baked into the artwork.** Tokens alone left the figures' shadows
   and all five poster prints green — invisible on a green page, murky against
   sand. Fixed with `scripts/loop-recolour-artwork.js`.
2. **Each poster got its own ground.** The first duotone normalised per image,
   so in the Lookbook one poster was bright sand and the next muddy brown. Now
   anchored on the field colour itself (all five agree on `#34b45c`).
3. **The transform script was broken as committed** — CommonJS in a
   `"type": "module"` package, so it threw on `require`. Converted to ESM.

Two *false* alarms also worth recording, both caused by the test harness rather
than the code: green figures on a mobile reload (browser cache serving the old
asset) and green Lookbook posters (script run from the wrong cwd, so its
relative asset path failed and it fell through to the live files). Both
disappeared once the harness was corrected — worth checking the harness before
believing a visual regression.

## Verification

  local artwork swapped in; zero green-dominant pixels remain in any asset
- `tsc --noEmit` clean for `/loop`
- Re-encoding took the eight assets from ~8.9MB to ~1.35MB
