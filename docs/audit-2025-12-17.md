# Odubo Platform Audit — December 17, 2025

## Executive Summary

This audit documents critical usability issues, design decisions, and implementation priorities based on hands-on mobile testing and creative director feedback.

---

## Critical Issues (P0)

### 1. Scroll Responsiveness — BROKEN
**Affected Areas:**
- Clips feed (only auto-scroll works, manual scroll blocked)
- Product detail modal
- Cart/Bag modal
- Album detail page
- Video detail modal
- General modal scroll behavior

**Root Cause:** Likely `touch-action`, `overflow`, or `overscroll-behavior` conflicts between nested scroll containers.

**Impact:** App feels unusable, high friction, users cannot navigate.

### 2. Video Player — NOT PLAYING
**Symptoms:**
- Clicking video shows thumbnail only
- No playback initiated
- Weird timestamps visible in background
- Clips visible behind modal (needs blur)

**Impact:** Core feature broken.

### 3. Album Detail Page — BROKEN
**Symptoms:**
- Random "0" characters appearing
- Cannot scroll track list
- Title overlapping cover art
- Songs don't play on tap
- Overall layout "atrocious"

**Impact:** Music feature unusable.

### 4. Moments/Capture — BROKEN
**Symptoms:**
- "Unable to load gallery information" error
- Galleries not loading images
- Capture flow not working

**Impact:** Community engagement feature broken.

---

## High Priority Issues (P1)

### 5. Drag-to-Close Mechanism
**Feedback:** "Too clunky, requires awkward precise movement"
**Decision:** Remove drag-to-close from ALL modals. Use X button consistently.
**Keep:** Entry/exit animations.

### 6. Media Priority System
**Requirement:** Single audio source at a time with clear priority:
- Music playing → clips muted but can browse
- User unmutes clips → music stops
- Video plays → everything else stops
- Return to clips → clips resume if no other media active

### 7. MiniBar Removal
**Decision:** Remove MiniBar completely.
**Replace with:** Vinyl player on clips as primary music indicator.
**Interaction:** Tap vinyl → opens larger music player modal.

## UI Specifications

### Modal Close Pattern
- Always show X button in header (top-left or top-right)
- X closes entire modal stack, returns to clips
- Remove drag handle and drag-to-close gesture
- Keep spring animations for enter/exit

### Scroll Containers
```css
/* Ensure scrollable content */
.modal-content {
  overflow-y: auto;
  -webkit-overflow-scrolling: touch;
  overscroll-behavior: contain;
  touch-action: pan-y;
}

/* Parent must not block */
.modal-container {
  touch-action: manipulation; /* or none on non-scroll areas */
}
```

### Media Player Modal
- Full-screen overlay when opened
- Takes priority over all other content
- Close returns to previous context
- Blur background content

### Video Player Design Reference
- Netflix/Disney+ style
- Clean playback controls
- "Up Next" queue visible
- Seamless flow between videos
- Blur clips feed in background

---

## Architecture Decisions

### Single Source of Audio
- Create `MediaPriorityContext` to manage which media source is active
- States: `idle`, `clips`, `music`, `video`
- Only one can be `playing` at a time
- Clips can be `browsing` while music is `playing`

### Modal Stack Management
- All modals share consistent close behavior
- X button always visible
- No drag-to-close
- Animations preserved
